# 耳机闹钟产品需求文档

## 1. 产品概述

### 1.1 产品目标

耳机闹钟是一款 Android 本地闹钟应用，解决系统闹钟在连接耳机时可能切换到扬声器、外放音量突然过大的问题。产品优先保证：

1. 已连接耳机时，只有确认音频实际进入耳机后才播放。
2. 耳机断开或路由失败时立即暂停声音，并继续震动和状态提示。
3. 所有闹钟调度、音频文件、设置和运行数据均只保存在本机。

### 1.2 目标用户

- 使用蓝牙耳机或有线耳机听音乐、播客或助眠音频的人。
- 在宿舍、合租房、家庭或办公环境不希望闹钟外放的人。
- 对闹钟数据与本地音频隐私敏感的人。

### 1.3 平台与版本

- 首发平台：Android 原生。
- 最低版本：Android 9.0（API 28）。
- 目标版本：Android 15（API 35）。
- iOS 不在首版范围。iOS 无法由普通应用可靠强制音频路由，后台准点闹钟能力也受系统限制。

## 2. MVP 范围

### 2.1 闹钟管理

- 新建、编辑、删除、启用和禁用多个闹钟。
- 每个闹钟可设置时间、名称、重复周期、铃声、震动和 Snooze。
- 重复周期支持“仅一次”及每周指定星期。
- 首页显示本地当前时间、待触发倒计时、闹钟时间、名称、重复摘要和启用状态。
- 首页优先显示最近一次普通触发或 Snooze。

### 2.2 响铃

- 到点后播放本地铃声并循环震动。
- 已连接耳机时，使用耳机目标设备启动媒体播放，静音确认实际路由后再渐入。
- 未连接耳机时，使用系统默认闹铃策略。
- 播放中耳机断开、路由离开目标耳机、音频焦点被抢占时停止音频，保留震动和高优先级通知。
- “延后 5 分钟”只创建当前实例的临时 Snooze，不修改原闹钟重复规则。
- “关闭闹钟”结束当前实例。
- 同一时间最多播放一个闹钟，其余实例进入持久化队列，按触发时间串行处理。
- 单次响铃最长 10 分钟，之后自动静音并保留状态通知。

### 2.3 铃声

- 提供随应用生成的内置提示音，不依赖网络或外部资源。
- 使用系统 Storage Access Framework 选择本地音频。
- 支持扩展名：`mp3`、`wav`、`m4a`、`aac`、`ogg`、`flac`。
- 实际可播放性以设备平台解码器为准；导入时立即验证。
- 导入成功后复制到应用私有目录，原文件移动或删除不会影响闹钟。
- 文件损坏或不可读取时回退内置提示音、继续震动并提示重新选择。

### 2.4 音量

- 应用内部增益默认 40%。
- 用户可在 10% 至 80% 之间配置上限。
- 应用不修改系统全局媒体或闹铃音量。
- 耳机模式下从 0 开始，通过约 300ms 渐入，避免突然大音量。

### 2.5 离线与隐私

- 应用 Manifest 不声明 `INTERNET` 权限。
- 不包含账号、分析、广告、云同步、远程配置或崩溃上报。
- 时间来自系统本地时钟，不进行网络校时。
- 闹钟数据库、设置和录音文件仅保存在应用私有目录。
- Android 自动备份和设备迁移备份均禁用。
- 卸载应用会删除应用私有数据。

## 3. 核心流程

### 3.1 新建闹钟

首页点击“新建闹钟” → 选择时间 → 输入名称 → 选择单次或每周重复 → 选择铃声 → 设置震动与 Snooze → 保存 → 立即计算并注册下一次精确触发。

### 3.2 耳机响铃

系统触发精确闹钟 → 前台服务启动 → 标记当前实例为响铃 → 提前注册下一次重复触发 → 检测耳机 → 静音启动 → 校验实际输出设备 → 路由确认后渐入 → 循环震动 → 用户关闭或 Snooze。

### 3.3 耳机断开

系统移除了目标输出设备，或播放器实际路由不再是目标耳机 → 立即停止并释放播放器 → 保持当前闹钟会话 → 持续震动 → 显示“耳机已断开”通知和重试入口。

### 3.4 多个闹钟接近触发

第一个实例进入响铃状态。后触发实例被标记为排队并显示状态通知。当前实例被关闭、Snooze 或自动静音后，队列中最早实例开始响铃。

## 4. 页面

| 页面 | 内容 |
|---|---|
| 首页 | 当前时间、下一个闹钟倒计时、权限告警、闹钟列表、启停开关、新建按钮 |
| 新建/编辑 | 时间、名称、单次/每周、星期选择、铃声、震动、Snooze、启停、删除 |
| 铃声选择 | 内置提示音、已导入文件、导入按钮、解码错误提示 |
| 响铃页 | 大号时间、闹钟名称、耳机名称、播放状态、延后 5 分钟、关闭、重试耳机 |
| 设置与隐私 | 音量上限、耳机状态、精确闹钟/通知/全屏/电池设置、勿扰限制、离线声明 |

## 5. 默认业务规则

- 新建闹钟默认启用、震动开启、Snooze 开启、使用内置铃声。
- 名称最大 40 字符，空名称保存为“闹钟”。
- 每周模式默认选中全部七天；用户必须保留至少一天。
- 精确闹钟权限缺失时仍允许创建闹钟，但使用尽力调度并显示显著警告。
- 时间不存在于夏令时跳变区间时，顺延到当天第一个有效分钟。
- 夏令时回拨产生重复本地时间时，只触发较早的那一次。
- 设备重启、时间改变、时区改变或应用升级后重建启用闹钟的下一次实例。

## 6. 异常与限制

### 6.1 音频路由

Android 的 `setPreferredDevice` 是首选设备而不是不可撤销的强制路由。应用可保证自身不会主动选择扬声器，并通过实际路由确认实现失败关闭，但以下情况仍可能发生：

- 系统音频策略短暂改变路由后应用才收到回调。
- OEM 将媒体音频强制路由到扬声器。
- 蓝牙耳机自身断连、没电或固件异常。
- 蓝牙重连或编解码器切换造成临时空窗。

在上述情况中，应用会尽快停止声音；无法承诺所有 OEM、所有蓝牙协议下绝对零漏音。

### 6.2 系统抑制

- 勿扰模式可能屏蔽媒体声音或震动，具体由系统策略决定。
- 用户强行停止应用后，Android 会取消后续闹钟。
- 厂商电池管理、自启动限制或省电模式可能延迟后台服务。
- 应用不会请求勿扰访问或直接绕过电池优化，只提供明确设置入口。
- 通知权限被拒绝时，精确广播仍可启动前台服务，但用户可能看不到全屏提示和故障通知。

### 6.3 格式

平台解码能力因 Android 版本和 OEM 而异。扩展名受支持不代表所有编码配置均可解码；导入验证失败时必须明确提示并允许重新选择。

## 7. 成功指标

- 在参考设备矩阵上，已连接耳机触发时声音仅进入耳机。
- 目标耳机断开后不出现持续扬声器播放。
- 精确权限开启时，后台、锁屏和重启恢复后的触发成功率满足验收用例。
- Snooze 在点击后 5 分钟触发，误差受系统精确调度限制。
- Manifest 始终不存在网络权限。
